            Cable
            
      
              
        
            1. Plug the host cable into the PC port. The unit appears as a card.
              2. 
        
            2. Insert the cable end. The pins row says module present.
              3. 
        
            3. Click Read cable. The plate shows the identity, the applications and the test features.
              4. 
        
            4. Click Save passport to write the plate to a record file.
              5. 
      
            
      
            Show details
        
            The tester is a single-port QSFP-DD stick. It talks to one cable end over the management bus and has no data lanes of its own. Two sticks and a cable make a two-end test.
            
        
            The pins row reads ModPrsL and IntL. Both low with no identity means a module is present or the rail is off. Turn MOD PWR on and read the cable.
            
        
            The unit carries its serial CT2M-NN and a small FRU record in its EEPROM. The card shows it under the unit name.
            
        
            Every field with a ? has a one-line meaning. The glossary below lists them all.
            
      
            
    
            
    
            
      
            Test a cable
            
      
              
        
            1. Choose one end or both ends, and the unit for each end.
              2. 
        
            2. Click Read cable. The label serial fills in, and the cable type matches the database.
              3. 
        
            3. Scan the label over the serial when the two differ. The operator name is yours to change.
              4. 
        
            4. Click Start the test. The page checks the switches and the module and tells you when one is off.
              5. 
        
            5. Watch the step card. It says what the running step reads and judges.
              6. 
        
            6. Read the verdict card. It names the next step. Copy the report for a ticket.
              7. 
      
            
      
            Show details
        
            The eight steps, what each reads and what it judges:
            
        
            
        
            A unit ships in AUTO with the slide switches at O. The software drives the control pins, so a technician never moves a switch. The pre-check reads the pins and names a switch only when it is off.
            
        
            A module starts in low power and draws under 1.5 W. High power is its working state. The tool watches temperature every second and pulls the module back to low power at its warning level.
            
        
            The module rail is built for 6 W. The tester refuses to release a module above the budget. A class 3 or higher module needs air over the sink.
            
        
            Back to setup stops a run before step 1 and keeps the form. Skip appears only on a step the engine marks as skippable, and it records your reason. Stop ends the run at any step.
            
        
            A cable without a criteria file runs without criteria, or you create a file from the cable on the Advanced page. With one end the PRBS step between two ends does not run.
            
      
            
    
            
    
            
      
            Advanced
            
      
              
        
            1. Pick a task tab: Read, Control, Run, Query, Derive or Features. Each button has a ? with its meaning.
              2. 
        
            2. On Run, two units on the host make a pair. A is the lower serial. Swap A and B changes which end sends first.
              3. 
        
            3. On Features, build the matrix. Exercise a row or a group to fill its result.
              4. 
        
            4. Decode every page shows the lane view first, then one block per CMIS page.
              5. 
        
            5. Tick both confirmations before a high-power command. A budget change needs a reason.
              6. 
        
            6. Run it. The result card and the chart fill in; the raw JSON sits behind a toggle.
              7. 
        
            7. On Derive, make a criteria file from the plugged cable and copy the git add line.
              8. 
      
            
      
            Show details
        
            PRBS is a known bit pattern a module generates and checks on its own lanes. BER is errors divided by bits. A raw optical link before error correction may read 1e-5 to 1e-4 and still be good.
            
        
            Some modules advertise a feature and return a placeholder. Examples: the same power on every lane, an SNR of 0 dB, a VDM page of zeros. The passport flags these, and a chart never plots an all-zero SNR series.
            
        
            During a trend or loopback run the checker's loss-of-lock flags are read every second. The register clears on read, so each amber cell shows the lanes that lost lock in that second.
            
        
            The Firmware card on Query reads the images and, with the vendor file, updates the inactive bank. The card says so when the update engine is not installed.

              2. 
        
            2. Type in the filter to find a cable or a unit.
              3. 
        
            3. Click a record to see its tables and charts.
              4. 
      
            
      
            Show details
        
            Every run writes the same files the command line writes: dumps, PRBS records, trend CSVs, passports and reports.
            
        
            An optical transceiver is one module with its own serial, so it gets one card and a two-end record appears under both. A copper cable is one cable with two end serials and one card.

            Show details
        
            Start the server with aectest web --open.
            
        
            This server owns the units it opened. Stop it before a command-line run on the same stick. A lock file refuses a second opener.
            
        
            The page keeps a heartbeat to the server. When the server stops, a banner says so and the page reconnects on its own. After a restart it reloads everything, and the form values stay.
            
        
            The server looks for units at start, on every page load, on Refresh units and every 10 s while no job runs.

            Troubleshooting
            
      
            SymptomCauseWhat to do
            
        
            NACK from slaveMODE is in MAN and the MSEL slide is at O or H, so the module is deselected.Set MODE to AUTO, then Refresh.
            
        
            pins low: module present or rail offThe module rail is off, so the pull-ups read low.Turn MOD PWR on and read the cable.
            
        
            interrupt latched since insertThe module raised IntL at insert for its latched flags. They clear on read.Read the cable. The flag names show on the pins row.
            
        
            No unit on the hostThe PC port is not connected, or another program holds the unit.Plug the PC port, close the other program, then Refresh units.
            
        
            Server restartedThe server process was started again.Nothing. The page reloads on its own and keeps your form values.
            
        
            Budget refusedThe module declares more power than the rail budget.Raise the budget with a reason on Advanced, or test a module within the budget.
            
        
            Label serial differsThe scanned label and the EEPROM serial do not match.Check the label. A real mismatch is a FAIL by design.
            
        
            Unit disconnected, No such deviceThe unit left the USB bus during a run: the host cable, or a latch-up of the FTDI.Unplug the host cable and the charger, wait 30 s, plug the host cable, then Refresh units.
            
        
            Cable removed during the testThe cable end came out of the cage mid-step.Seat it again and start the test over. The stopped run stays on record.
            
        
            Connection lost during the runThe server stopped mid-run.Wait for Live in the corner, then start the test again. The log keeps the last state.
