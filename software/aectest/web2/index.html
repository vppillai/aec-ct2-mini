          Cable
          
      
          1. Plug the host cable into the PC port. The unit appears as a card.
          2. Insert the cable end. The pins row says module present.
          3. Click Read cable. The plate shows the identity, the applications and the test features.
          4. Click Decode all pages for every CMIS field, page by page, with a lane view.
          5. Click Save passport to write the plate to a record file.
          
      
          Show details
          The tester is a single-port QSFP-DD stick. It talks to one cable end over the management bus and has no data lanes of its own. Two sticks and a cable make a two-end test.
          The pins row reads ModPrsL and IntL. Both low with no identity means a module is present or the rail is off. Turn MOD PWR on and read the cable.
          Every field with a ? has a one-line meaning. The glossary lists them all.
          
    
          Test
          
      
          1. Choose one end or both ends, and the unit for each end.
          2. Click Read cable. The label serial fills in, and the cable type matches the database. The setup says what will run.
          3. Scan the label over the serial when the two differ. The operator name is yours to change.
          4. Click Start the test. The step card says what runs now, how long it takes and what it waits for. Stop sits at the top right for the whole run.
          5. Read the verdict card: the word, why, and the next step. Test another cable, open the record or copy the report from it.
          
      
          Show details
          A unit ships in AUTO with the slide switches at O. The software drives the control pins, so a technician never moves a switch. The pre-check reads the pins and names a switch only when it is off.
          A module starts in low power and draws under 1.5 W. High power is its working state. The tool watches temperature every second and pulls the module back to low power at its warning level.
          Back to setup stops a run before step 1 and keeps the form. Skip appears only on a step the engine marks as skippable, and it records your reason.
          
    
          The test steps
          The same text the step card shows during a run.
          
    
          Explore
          
      
          1. Pick a tab by task: Read, Control, Run, Query, Firmware, Database, Features.
          2. On Run, two units on the host make a pair. A is the lower serial. Swap A and B changes which end sends first.
          3. On Features, build the matrix. Exercise a row or a group to fill its result.
          4. Each command card says what it does and what it needs. A Run command needs both guard boxes and a budget reason when the budget changes.
          5. Run it. The result cards, the lane view and the chart fill in. The raw JSON sits behind a toggle.
          6. On Firmware, Plan never writes. Read the plan, then Update. Run and Commit are separate steps with their own flags.
          
      
          Show details
          PRBS is a known bit pattern a module generates and checks on its own lanes. BER is errors divided by bits. A raw optical link before error correction may read 1e-5 to 1e-4 and still be good.
          Some modules advertise a feature and return a placeholder. Examples: the same power on every lane, an SNR of 0 dB, a VDM page of zeros. The Cable page lists these as hollow features.
          
    
          Records
          
      
          1. Runs group by cable, with the serial on the card.
          2. Type in the filter to find a cable or a unit.
          3. Click a record to see its cards and charts. A page dump opens as the decode tree.
          
    
          Settings
          
      
          1. Pick light or dark.
          2. Read the server instance, the budget, the record folders and the command of record.
          
      
          Show details
          Start the server with aectest web2 --open. aectest web --open starts the first front end.
          This server owns the units it opened. Stop it before a command-line run on the same stick. A lock file refuses a second opener.
          The page keeps a heartbeat to the server. When the server stops, a banner says so and the page reconnects on its own. After a restart it reloads everything, and the form values stay.

          Troubleshooting
          
      
          SymptomCauseWhat to do
          
        
          The module does not answer (NACK)MODE is in MAN and the MSEL slide is at O or H, so the module is deselected.Set MODE to AUTO, then Refresh.
          
        
          pins low: module present or rail offThe module rail is off, so the pull-ups read low.Turn MOD PWR on and read the cable.
          
        
          interrupt latched since insertThe module raised IntL at insert for its latched flags. They clear on read.Read the cable. The flag names show on the pins row.
          
        
          No unit on the hostThe PC port is not connected, or another program holds the unit.Plug the PC port, stop the other program, then Refresh units.
          
        
          The unit is open in another programAn older server or a command-line run holds the lock.Stop that program, then Refresh units.
          
        
          Server restartedThe server process was started again.Nothing. The page reloads on its own and keeps your form values.
          
        
          Budget refusedThe module declares more power than the rail budget.Raise the budget with a reason on Explore, or test a module within the budget.
          
        
          Label serial differsThe scanned label and the EEPROM serial do not match.Check the label. A real mismatch is a FAIL by design.
          
        
          USB LED on, PC LED offThe FT2232H does not enumerate: a latch-up on the FTDI rail.Unplug the host cable and the charger, wait 30 s, plug the host cable alone.
